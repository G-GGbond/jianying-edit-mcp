# 为什么剪映版本这么要紧

这个工具不是"调用剪映的界面"，而是**直接读写剪映的工程文件、调用剪映的渲染引擎**。
所以剪映版本一变，下面三样可能同时变，任何一样对不上就会失败。

## 会变的三样东西

| 东西 | 说明 | 变了会怎样 |
|---|---|---|
| **草稿结构版本** | 工程 JSON 的结构版本号，如 `110.0.0`、`189.0.0` | 版本太低打不开、太高被拒；字段含义变化会导致元素错乱 |
| **草稿加密方式** | 6.0 起主文件改名 `draft_info.json` 且内容加密 | 旧的读取方式直接读不出 JSON |
| **`videoeditor.dll` 的导出入口** | 无头导出要按 ABI 找到 `restoreDraft`/`exportFactory` 等入口 | 入口找不到 → 导出报错 |

## 实际报错长什么样

| 现象 | 原因 |
|---|---|
| `jy-draftc` 自检报 `version mismatch` / `DLL 版本不符` | jy-draftc 不是给这个剪映版本编译的 |
| `-c` 自检里 `export entries: x/16` 不满 16 | 导出入口解析不全，这个版本不适配 |
| 结构升级报 `target 版本低于源版本` | 草稿结构版本比目标高 |
| 剪映能打开但**字幕错位、素材丢失** | 结构版本不匹配，字段语义不同 |
| 剪映报"草稿已损坏" | 加密回环失败或结构校验没过 |

## 怎么知道自己该用哪套

各组件版本是**绑死的**，不能混搭：

```
剪映专业版 11.6.0.14552
  ↕ 必须配套
jy-draftc 11.6.0.14552-26101320（同上版本号）
  ↕ 结构版本
jy_build --structuralVersion 189.0.0（该 jy-draftc 支持的上限）
```

查当前状态：

```powershell
jianying-edit doctor
```

返回里这几个字段要能对上：

```json
{
  "jianyingVersions": ["11.6.0.14552"],
  "jyDraftcVersion": "jy-draftc 26101320 (jianying 11.6.0.14552)"
}
```

括号里的剪映版本必须和 `jianyingVersions` 一致。不一致就是混搭了。

## 不同剪映版本怎么办

| 你的剪映 | 该做什么 |
|---|---|
| 11.6.0.14552（已验证） | 直接用，`structuralVersion` 用默认 `189.0.0` |
| 其他 11.x | 去 [jy-draftc releases](https://github.com/wenshui330/jy-draftc/releases) 找对应版本号；没有就说明还没适配 |
| 10.x 及以下 | 结构版本要调低（如 10.6 对应约 179.0.0），且 jy-draftc 要用对应版本 |
| **5.9 及以下** | 草稿是**明文**，另一条技术路线。用 [jianying-editor-skill](https://github.com/isYangs/jianying-editor-skill) 更合适——它支持 5.9 且能 UI 自动化导出 |
| 想升级剪映 | **先别升**。等 jy-draftc 出对应版本再升，否则整条链断掉 |

## 最省心的做法

**装好之后立刻关掉剪映的自动更新。**

剪映设置里有一个"自动更新"开关。关掉它，你就能一直用这套验证过的版本组合。
一旦它偷偷升到 11.7/11.8，加解密和导出会一起失效，而 jy-draftc 未必当天就出新包。

升级的正确姿势：

1. 先看 jy-draftc 有没有出新版本适配
2. 有 → 下载新 jy-draftc，再升剪映
3. 没有 → 别升

## 为什么不能"自适应"

理论上可以自己识别版本并转换结构，但：

- 草稿结构的字段语义在版本间有实质变化，不是简单改个版本号
- 加密算法依赖 `videoeditor.dll` 里的实现，只能通过它的公开入口调用
- 只有 jy-draftc 那样针对每个版本逆向并校验的项目才能可靠处理

所以这个项目选择**明确绑定版本 + 靠工具升级**，而不是假装兼容一切。
